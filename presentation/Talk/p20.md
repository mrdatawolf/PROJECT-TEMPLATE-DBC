## Proof this isn't just a nice diagram

[Slide 20 — CONTRACT-007]

Real example, from a production repo, MeshtasticForeman. Task: add Zod
validation across REST routes. Sounds boring. It flagged its own biggest
risk without me having to go looking for it: today, `since=banana` on a
query silently means "no time filter" — the query just gets wider than
intended, no error. Meanwhile `/api/traceroutes` already rejects the same
malformed input with a 400. One shared `since` schema has to pick *one*
behavior across eleven endpoints. The contract didn't guess which — it
enumerated the conflict, gave a recommendation, and left the decision to
me, because tightening validation silently changes behavior for eleven
endpoints at once. That's exactly the kind of decision that gets buried in
a diff if nobody's forcing it into an open-questions section first.
