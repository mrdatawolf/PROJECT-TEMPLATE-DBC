For as long as I can remember the constraint on software was writing the code to
implement a decision or goal, so that's where we allocated our resources. We wrote 
just enough spec to start coding, we fixed the design later in v3 or our dreams; 
since "later" was cheap to defer to.

AI coding agents seem to break that assumption. Execution is now so fast it is 
genuinely disposable. What doesn't get cheaper is deciding what "correct" means 
and who's accountable when it isn't. That decision still takes a human brain, and 
it still takes exactly as long as it always did.

So this talk is really about one idea, seen from a few different angles:
write the decision down once, precisely, as a contract — then execution
stops being the risky part. It doesn't matter if the implementer is this LLM,
that LLM, or a person. When requirements change, you don't patch old assumptions, 
you write a new contract and let execution honor it at AI speed. Everything else 
I'm going to show you — the pipeline diagrams, the DbC vocabulary, the directory 
structure, the real examples from production repos — is scaffolding around that 
one claim.
