For as long as I can remember the constraint on software was writing the code to
implement a decision or goal, so that's where we allocated our resources. We wrote 
just enough spec to start coding, we fixed the design later in v3 or our dreams; 
as "later" was cheap. We said it was part of the Technical Debt

AI coding agents seem to break that assumption. Coding is now so fast code is 
genuinely disposable. What doesn't get cheaper is deciding what "correct" means 
or who's accountable accoutable for it. That still takes a human brain, and 
I am arguing that is where the time 'freed' should be spent instead.

So this talk is really about one idea, seen from a few different angles:
write the decision down once, precisely, as a contract — then execution
stops being the important part. It doesn't matter if the implementer is this LLM,
that LLM, or a person. When requirements change, you don't patch old assumptions, 
you write a brand new contract and let execution honor it at AI speed. Everything else 
I'm going to show you — pipeline diagrams, the DbC vocabulary, the directory 
structure, the real examples from production repos — is just trying to prove that 
claim.
