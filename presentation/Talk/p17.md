[Slide 17 — authority rules]

Every transition has exactly one owner. Only a human moves proposed to
approved. An assigned implementer moves approved to in-progress. The
implementer moves work to review, but only after recording a handoff.
The reviewer records findings — it does not implement fixes and it does
not accept the task; that's a second independent role, on purpose. Only a
human moves work to completed.

Instruction precedence, if you're wondering how conflicts get resolved:
direct human instruction and the current task outrank everything, then
CLAUDE.md foundational rules, then AGENTS.md with nearest-scope-wins, then
approved contracts in scope, then project docs and accepted ADRs, then the
task plan itself. Same idea as `/etc` defaults versus user config — more
specific clarifies, it never silently overrides.
